#### 10.11 스위프트에서 self 사용하기
스위프트 프로그래밍 언어는 현재의 클래스 인스턴스에 속한 메서드나 프로퍼티를 가리킬 때를 위한 self 프로퍼티 타입을 제공함.

대부분의 경우 스위프트에서 self는 선택적으로 사용.

* self를 사용해야 하는 상황:
    - 프로퍼티나 메서드를 클로저 표현식 내에서 참조할 경우.
    - 함수의 매개변수가 클래스 프로퍼티와 동일한 이름을 가질 경우

* self 사용 여부는 프로그래머의 취향에 달림. 프로퍼티나 메서드를 참조할 때 self를 사용하기 좋아하는 프로그래머들도 자신이 원하는 방식으로 스위프트 코딩을 계속해 갈 수 있음. 하지만, 스위프트로 프로그래밍할 때 self를 반드시 사용해야 하는 것은 아님.

#### 10.13 불투명 반환 타입

* **불투명 반환 타입(opaque return type)**
    : (앞 세션에 이어서)
    - 공개 API 내에서 사용되는 반환 타입을 숨기기 위해 의도적으로 이렇게 설계됨. 구체화된 타입을 감춤으로써 프로그래머는 특정 구체화된 타입을 반환하는 함수에 의존하지 않게 되거나 접근되지 않는 내부 객체에 접근하게 되는 위험이 없어짐. 또한, API 개발자가 다른 프로토콜과 호환되는 타입을 반환하도록 수정하는 등의 내부 구현체를 변경할 때, API를 사용하는 모든 코드의 의존성이 깨질까라는 염려를 하지 않아도 되는 장점도 있음.

    ```swift
    let intOne = doubleFunc1(value: 10)
    leet stringOne = doubleFunc2(value: "Hello")

    if (intOne == stringOne) {
        print("They match")
    }
    ```

    두 함수의 소스코드에 접근할 수 없어서 코드가 유효한지를 알 수 없다는 전제로 예제 코드를 보자. 비록 우리는 이들 함수가 반환하는 구체화된 타입을 알 수 있는 방법은 없지만, 다행히도 스위프트 컴파일러는 숨겨진 정보에 접근할 수 있다. 따라서 앞의 코드는 유효하지 않은 코드를 실행하려고 하는 지점 앞에서 다음과 같은 구문 오류를 발생할 것.

    불투명 반환 타입은 SwiftUI API의 기본 토대, SwiftUI로 앱을 개발할 때 널리 사용됨.

    SwiftUI는 작고 재사용 가능한 빌딩 블록을 모으고 거대한 뷰 선언부를 작고 가벼운 하위 뷰들로 리팩토링하여 앱을 만들도록 함. 각각의 빌딩 블록은 일반적으로 View 프로토콜을 따름. 이들 빌딩 블록을 View 프로토콜을 따르는 불투명 타입으로 반환하도록 선언함으로써 매우 유연하며 상호호환성 있는 빌딩 블록이 되며, 그 결과로 더 깔끔하고 재사용과 유지보수하기 쉬운 코드가 됨.

- **데이터 캡슐화(data encapsulation)**: 클래스에 저장되고 접근될 수 있는 데이터는 오직 해당 클래스 내에 정의된 메서드만을 통해서 된다는 것. 클래스 내의 캡슐화된 데이터를 **프로퍼티** 또는 **인스턴스 변수(instance variable)**이라고 함.

* "접근되지 않는 내부 객체에 접근하게 되는 위험" -> "API 내부 구현에 사용되는 타입을 외부 사용자에게 불필요하게 노출하지 않을 수 있음."라고 이해하는 편이 좋음. 저 정확하고 쉽게 바꾼 것.

* `struct`는 Swift에서 여러 데이터와 기능을 묶어 새로운 타입을 만드는 방법.
    - `struct`는 단순한 데이터 상자보다 조금 더 넓게, **"관련된 데이터와 기능을 묶어서 하나의 타입으로 만드는 것"**

* `-> some Protocol`은 "실제로는 특정한 하나의 구체 타입을 반환하지만, 외부에는 그 타입의 이름 대신 이 Protocol을 만족한다는 사실만 공개하겠다."라는 의미.
