1. (추가 질문 체크하기)(어제의 5에 대한 질문과 답) 5번(어제, 이전 것)의의 옵셔널은 '값이 있음'과 '값이 없음'을 함께 표현하는 타입.
    - `let number = score`: 옵셔널 값을 그대로 받음. number의 타입은 `Int?`
    - `if let number = score`: 값이 있는지 확인하고, 있으면 내부 정수를 받음. number의 타입 `Int`
    * `let`만 보고 해석하지 말고, `if let`을 하나의 문법으로 봐야 함. 이것을 옵셔널 바인딩(optional binding)이라고 함.
    - `score!`는 강제 언래핑.
    * `.some(10)`은 옵셔널의 '값이 있는 상태'를 명시한 표기
        `let first: Int? = 10`
        `let second: Int? = .some(10)`
        위 두 줄은 같은 상태를 만듬.
        
        `Int?`의 정식 표기는 `Optional<Int>`이며, 옵셔널에는 `.some(값)`과 `.none`이라는 두 경우가 있음. `nil`은 값이 없는 경우를 표현함.
        - `some(10)`: 옵셔널 안에 정수 10이 있음
        - `.none`, `nil`: 옵셔널 안에 값이 없음
        - `some Equatable`: 반환값의 타입을 설명하는 별도의 문법

3. (다시 체크) 8번의 '기본값'은 인자를 생략했을 때 대신 사용하는 값.
    - `inout`은 함수 안에서 바꾼 값을 호출한 쪽의 변수에 반영하는 매개변수 표시.
        - 함수 선언, `inout Int`, 받은 정수를 수정해 원래 변수에 반영
        - 함수 호출, `&변수명`, 변경을 반영할 변수로 `변수명`dmf wjsekf
        - 동작: 기존 값 가져오기 -> 함수 안에서 수정하기 -> 원래 변수에 반영하기
        - 일반 매개변수는 함수 안에서 상수처럼 취급하지만, inout 매개변수에는 새 값을 대입할 수 있음. 그리고 변경을 반영할 자리가 필요하므로 let 상수나 숫자 리터럴 대신 변경 가능한 변수를 전달해야 함.

7. (다시 체크) 12번(이전 것)의 '타입 메서드', 'deinit', '캡슐화'는 각각 '호출 대상', '해제 시 정리', '상태를 다루는 방식'에 관한 개념.
    - 인스턴스 메서드 = 선언: `func add(...)`, 호출 대상: 특정 인스턴스
    - 타입 메서드 = 선언: `static func describe()`, 호출 대상: 타입 자체

    - `deinit`은 클래스 인스턴스가 해제되기 직전에 자동으로 실행되는 정리 코드.
    - `nil`을 대입하면서 그 참조를 내려놓고, 다른 강한 참조가 없으므로 인스턴스가 해제되고 `deinit`이 실행됨.

    - '캡슐화'는 '데이터와 관련 동작을 하나의 타입으로 묶고, 외부에서 상태를 다루는 방식을 정하는 것'
    - '접근 제어'는 캡슐화를 구현하는 수단.

8. (다시 체크)'처음 사용할 때 초기값을 계산해 저장한다.' 여기서 '계산'은 산술뿐 아니라 초깃값을 얻는 코드를 실행하는 것을 넓게 뜻함.
    - 끝의 `()`: 이 표현식을 평가할 때 클로저를 호출.
    - `lazy`: 그 초기화 표현식을 평가할 시점을 처음 접근할 때까지 미룸.
    - 프로퍼티의 종류와 값을 얻는 방식
        - 일반 저장 프로퍼티: 인스턴스를 초기화할 때 값을 마련해 저장
        - lazy 저장 프로퍼티: 처음 접근할 때 초기값을 마련해 저장
        - 계산 프로퍼티: 읽을 때 getter 코드를 실행해 값을 제공

9. (다시 체크) `{ get }`는 '이 프로퍼티를 읽을 수 있어야 한다'는 프로토콜의 요구사항.
    - `{ get set }`을 요구한다면 읽기와 쓰기를 모두 제공해야 하므로, `let` 저장 프로퍼티로는 충족할 수 없음.

10. `some Equatable`: '구현이 정한 특정 타입이 있으며, 그 타입은 동등 비교를 지원한다'는 뜻.
    - `Equatable`: 동등 비교 기능을 요구하는 프로토콜
    - 반환형의 `some`: 구체적인 타입 이름을 공개하지 않고 특정 타입을 나타내는 표시
    - `some Equatable`: `Equatable`을 준수하는, 구현이 정한 특정 타입

    - `some`에서는 구체 타입이 존재하고 컴파일러도 그 타입을 알지만, 호출하는 코드는 공개된 타입 조건을 기준으로 사용함. 이런 타입을 불투명 타입, 또는 책의 표현으로 불특정 타입이라고 부름.

    - "모든 반환 경로의 구체 타입이 같아야 함"

    - 서로 다른 선언의 불투명 반환 타입은 별도로 취급됨. 두 함수가 내부에서 우연히 같은 Int를 사용하더라도, 그 사실을 호출하는 쪽에 타입 관계로 공개한 것은 아님.

11. (다시 체크) `body: some View`는 '`body`라는 프로퍼티가 제공하는 값의 타입'을 설명함.
    - `some View`의 뜻: 구체적인 타입은 구현이 정하지만, 그 타입이 `View`를 준수한다는 사실을 제공함.
