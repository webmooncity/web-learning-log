이전 5번의 두 runTask 코드는 ‘정의’와 ‘호출’이므로 역할이 다릅니다.
질문하신 두 코드를 그대로 구분하면 다음과 같습니다.
코드	역할
func runTask(...) { ... }	runTask가 어떤 작업을 할지 정의
runTask(completion: ...)	정의된 runTask에 인자를 전달하며 호출


먼저 전체 예제 A를 보겠습니다.
// ① runTask 함수를 정의합니다.
func runTask(completion: (Bool) -> Void) {
    completion(true)
}

// ② 전달할 클로저를 만들어 handler에 담습니다.
let handler = { (success: Bool) -> Void in
    print(success)
}

// ③ runTask를 호출하면서 handler를 전달합니다.
runTask(completion: handler)

여기에는 두 가지 실행 기능이 있습니다.
실행 기능	하는 일
runTask	전달받은 함수를 true와 함께 호출
handler에 담긴 클로저	전달받은 Bool 값을 출력


먼저 runTask의 매개변수를 보겠습니다.
completion: (Bool) -> Void

앞의 show는 Int를 받았습니다.
number b: Int

이번 runTask는 함수를 받습니다. 받을 함수의 형태가 (Bool) -> Void인 것입니다.
completion: (Bool) -> Void

다음 두 가지 입력 단계를 구분해야 합니다.
- runTask를 호출할 때는 **함수 값 handler**를 전달합니다.
- runTask 안에서는 그 함수를 호출하면서 **불리언 값 true**를 전달합니다.
실행 과정을 따라가 보겠습니다.
순서	실행
1	handler에 클로저를 담습니다. 아직 print는 실행하지 않습니다.
2	runTask(completion: handler)를 호출합니다.
3	runTask 안에서는 전달받은 클로저를 completion이라는 이름으로 사용합니다.
4	completion(true)가 그 클로저를 호출합니다.
5	클로저의 success가 전달받은 true를 나타냅니다.
6	print(success)가 true를 출력합니다.


클로저의 문법도 나누어 보겠습니다.
{ (success: Bool) -> Void in
    print(success)
}

부분	의미
(success: Bool)	불리언 값을 하나 받고 success라는 이름으로 사용
-> Void	의미 있는 결과값을 반환하지 않음
in	매개변수·반환 타입 부분과 실행할 코드 부분의 경계
print(success)	호출되었을 때 실행할 코드


이제 **‘별도의 상수에 담지 않고 바로 전달한다’**를 설명하겠습니다.
숫자로 보면 익숙한 차이입니다.
let amount = 5
show(number: amount)

위 코드는 5에 이름을 붙인 뒤 전달합니다. 다음처럼 숫자를 바로 적어도 됩니다.
show(number: 5)

함수 값도 같은 방식으로 전달할 수 있습니다.
let handler = { (success: Bool) -> Void in
    print(success)
}

runTask(completion: handler)

여기서 handler 자리에 그 상수에 담았던 클로저 표현식 자체를 적을 수 있습니다.
다음은 같은 동작을 하는 전체 예제 B입니다.
// runTask의 정의는 그대로입니다.
func runTask(completion: (Bool) -> Void) {
    completion(true)
}

// 호출할 때 클로저를 직접 전달합니다.
runTask(completion: { (success: Bool) -> Void in
    print(success)
})

completion(true)는 빠지지 않았습니다. 위의 함수 정의 안에 그대로 있습니다.
아래쪽의 중괄호는 runTask의 본문을 다시 작성한 것이 아니라, runTask에 인자로 넘기는 클로저입니다.
다음으로 **후행 클로저(trailing closure)**는 이 클로저 인자를 함수 호출 괄호 뒤로 옮겨 적는 문법입니다.
타입을 문맥에서 알 수 있으므로 먼저 이렇게 줄일 수 있습니다.
runTask(completion: { success in
    print(success)
})

그 클로저를 호출 괄호 밖으로 옮기면 다음과 같습니다.
runTask() { success in
    print(success)
}

다른 인자가 없으므로 빈 ()도 생략할 수 있습니다.
runTask { success in
    print(success)
}

이 세 가지는 같은 호출을 다르게 적은 것입니다. 실제로 사용할 때는 하나를 선택하시면 됩니다. 어느 표기를 사용하든, 위에 정의한 runTask 안의 completion(true)가 실행됩니다. docs.swift.org
‘후행’은 코드를 적는 위치를 뜻합니다. 클로저가 언제 실행되는지는 runTask 안에서 어디서 호출하느냐에 따라 결정됩니다.

캡처는 Swift의 정식 개념이며, ‘정의된 위치의 바깥 변수’와 ‘그 변수의 수명’을 함께 이해하면 더 정확해집니다.
이전 예제를 다시 가져오겠습니다.
func makeCounter() -> () -> Int {
    var count = 0

    func next() -> Int {
        count += 1
        return count
    }

    return next
}

let counter = makeCounter()

print(counter()) // 1
print(counter()) // 2

next 안에는 count를 새로 선언하는 줄이 없습니다. 자신을 둘러싼 함수에 선언된 count를 사용합니다.
이 경우 반환되는 클로저는 개념적으로 다음 두 가지를 함께 가진다고 생각하시면 됩니다.
실행할 next의 코드 + 그 코드가 사용하는 count에 대한 연결

이 연결 덕분에 makeCounter()의 실행이 끝나도 count가 유지됩니다.
관련 개념을 구분하면 다음과 같습니다.
개념	이 예제에서의 의미
어휘적 스코프	코드가 정의된 위치를 기준으로 사용할 수 있는 이름이 정해짐
캡처	next가 바깥의 count를 계속 사용할 수 있게 함
수명	캡처된 상태가 필요한 동안 유지됨


어디에서 counter()를 호출하든, 자신이 만들어질 때 연결된 count를 사용합니다. 호출하는 곳에 우연히 같은 이름의 변수가 있다고 해서 그것을 사용하는 것은 아닙니다.
그리고 makeCounter()를 새로 호출하면 새 count가 생깁니다.
let first = makeCounter()
let second = makeCounter()

print(first())  // 1
print(first())  // 2
print(second()) // 1

주변의 모든 지역 변수를 통째로 복사하는 규칙이 아니라, 클로저가 사용하는 바깥의 상수·변수에 필요한 접근을 유지하는 기능입니다. GitHub
조금 더 정교하게 제어하는 문법으로 **캡처 리스트(capture list)**도 있습니다.
func demonstrateCapture() {
    var number = 0

    let readCurrent = {
        number
    }

    let readInitial = { [number] in
        number
    }

    number = 10

    print(readCurrent()) // 10
    print(readInitial()) // 0
}

demonstrateCapture()

이 예제에서는 다음 차이가 있습니다.
클로저	무엇을 사용하나요?
readCurrent	바깥의 변경 가능한 number
readInitial	클로저를 만들 때 [number]로 받아 둔 정수 값 0


[number]는 클로저 생성 시점에 해당 값으로 별도의 캡처 항목을 초기화합니다. 여기서는 Int이므로 그 시점의 정수 값을 보관한 것으로 이해하시면 됩니다.

클래스는 타입의 한 종류이고, 강한 참조는 클래스 인스턴스를 살아 있게 유지하는 참조입니다.
먼저 타입과 클래스를 구분하겠습니다.
class StudySession {
    var minutes = 0
}

let session = StudySession()

코드	의미
class	클래스를 정의하는 키워드
StudySession	새로 정의한 클래스 타입
StudySession()	그 타입의 인스턴스를 생성
session	만들어진 인스턴스를 가리키는 상수


따라서 StudySession을 ‘클래스’라고 부르거나 ‘타입’이라고 부르는 것 모두 문맥상 가능합니다.
다만 타입이 더 넓은 개념입니다. class뿐 아니라 struct, enum으로도 새로운 타입을 정의할 수 있습니다.
static func는 구조체나 열거형에서도 사용할 수 있기 때문에, 이를 통틀어 타입 메서드라고 부릅니다. ‘클래스 메서드’보다 범위가 넓은 표현입니다. Documentation
다음으로 **참조(reference)**는 특정 인스턴스를 가리키는 연결입니다.
class Note {
    deinit {
        print("인스턴스 해제")
    }
}

var first: Note? = Note()
var second: Note? = first

여기서 Note()로 만든 인스턴스는 하나입니다.
second = first는 새 인스턴스를 만드는 코드가 아닙니다. 같은 인스턴스를 가리키는 참조가 하나 더 생깁니다.
이제 참조를 하나씩 없애겠습니다.
first = nil
// second가 같은 인스턴스를 계속 가리키므로 아직 해제되지 않음

second = nil
// 마지막 강한 참조가 사라짐 → "인스턴스 해제"

상태	인스턴스를 유지하는 참조
두 변수에 연결된 상태	first, second
first = nil 이후	second
second = nil 이후	없음


강한 참조(strong reference)는 그 참조가 유지되는 동안 인스턴스가 해제되지 않도록 붙잡는 참조입니다. Swift에서 클래스 인스턴스에 대한 일반적인 참조는 기본적으로 강한 참조입니다.
이 수명을 관리하는 방식이 ARC, 자동 참조 계수입니다. 마지막 강한 참조가 해제되면 인스턴스가 정리되며, 그 과정에서 deinit이 실행됩니다. Apple Developer

‘프로퍼티’와 ‘계산 프로퍼티’를 이해하면, var title: String { "Swift" }가 왜 등장했는지도 연결됩니다.
먼저 타입 안에 변수를 넣어 보겠습니다.
struct StudyNote {
    var title: String = "Swift"
}

let note = StudyNote()
print(note.title) // Swift

여기서 title처럼 타입 안에 정의되어 인스턴스를 통해 사용하는 값의 구성 요소를 프로퍼티(property, 속성)라고 부릅니다.
note.title은 ‘이 노트의 제목’을 읽는 코드입니다.
이번 title은 저장 프로퍼티입니다.
var title: String = "Swift"

초깃값 "Swift"를 저장하고, 읽을 때 저장된 값을 제공합니다.
이번에는 계산 프로퍼티입니다.
struct ComputedNote {
    var title: String {
        return "Swift"
    }
}

let note = ComputedNote()
print(note.title) // Swift

계산 프로퍼티는 결과값을 자체 저장해 두는 대신, 읽을 때 코드를 실행해 값을 제공합니다.
이 예제는 읽으면 "Swift"를 반환하도록 정의했습니다.
코드	의미
var title: String = "Swift"	문자열을 저장
var title: String { return "Swift" }	읽을 때 문자열을 반환하는 코드 실행


단일 표현식이면 return을 생략할 수 있습니다.
var title: String {
    "Swift"
}

앞선 답변에서는 이 계산 프로퍼티 문법을 보여드리려고 이렇게 작성했습니다. 항상 같은 문자열만 필요하다면 저장 프로퍼티로 작성해도 됩니다. 고정 문자열 예제만으로는 계산 프로퍼티의 필요성이 잘 드러나지 않았습니다.
실제 계산이 있는 예제를 보겠습니다.
struct StudyTime {
    var minutes = 30

    var seconds: Int {
        minutes * 60
    }
}

var study = StudyTime()

print(study.seconds) // 1800

study.minutes = 60

print(study.seconds) // 3600

seconds를 읽을 때마다 현재 minutes를 사용해 결과를 제공합니다. 따라서 minutes를 바꾸면 다음에 읽는 결과도 달라집니다. Documentation
값을 읽을 때 실행하는 이 부분을 getter라고 합니다. 길게 쓰면 다음과 같습니다.
var seconds: Int {
    get {
        return minutes * 60
    }
}

읽기 전용 계산 프로퍼티에서는 get을 생략할 수 있고, 단일 표현식에서는 return도 생략할 수 있습니다.
중괄호 안에 코드가 있어도 사용법은 프로퍼티입니다.
study.seconds   // 프로퍼티 읽기
// study.seconds() // 함수 호출 문법이므로 사용할 수 없음
