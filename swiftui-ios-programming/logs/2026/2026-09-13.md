#### 10.13 불투명 반환 타입 (복습)

* **불투명 반환 타입(opaque return type)**:
    - 특정 반환 타입(**구체화된 타입, conrete type**)을 지정하는 대신, 불투명 반환 유형을 사용하면 지정된 프로토콜을 따르는 모든 타입이 반환될 수 있게 함.
    - 프로토콜 이름 앞에 some 키워드를 붙여 선언.

    - (ChatGPT로 개념 설명 도움받음) Equatable:
        - Swift의 프로토콜(protocol)
        - 이 타입의 값끼리 `==`, `!=`로 비교할 수 있다.
        - `some Equatable`: Equatable을 준수하는 구체적인 어떤 타입 하나.
        - `some Equatable`은 `Equatable` 중에서 하나으 ㅣ고정된 구체 타입을 숨기는 것이지, 실행할 때마다 아무 `Equabable` 타입이나 골라 반환하는 것이 아님.
        - 총 정리, `some Equatable` = `Equatable`을 준수하는 특정한 하나의 구체 타입이 존재하지만, 그 구체 타입의 이름은 외부에 숨기겠다는 듯.

    - 우리는 실제 반환 타입을 아는 게 아니라 반환 타입의 자격에 대해 아는 것.

    * 공개 API 내에서 사용되는 반환 타입을 숨기기 위해 의도적으로 설계.
    * 구체화된 타입을 감춤으로써 프로그래머는 특정 구체화된 타입을 반환하는 함수에 의존하지 않게 되거나 접근되지 않는 내부 객체에 접근하게 되는 위험이 없어짐.
    * 또한, API 개발자가 다른 프로토콜과 호환되는 타입을 반환하도록 수정하는 등의 내부 구현체를 변경할 때, API를 사용하는 모든 코드의 의존성이 깨질까라는 염려를 하지 않아도 되는 장점도 있음.

    * 불투명 반환 타입은 SwiftUI API의 기본 토대이며, SwiftUI로 애븡ㄹ 개발할 때 널리 사용됨. SwiftUI는 작고 재사용 가능한 빌딩 블록을 모으고 거대한 뷰 선언부를 작고 가벼운 하위 뷰들로 리팩토링하여 앱을 만들도록 함. 각각의 빌딩 블록은 일반적으로 View 프로토콜을 따름. 이들 빌딩 블록을 View 프로토콜을 따르는 불투명 타입을 반환하도록 선언함으로써 매우 유연하며 상호호환서 있는 빌딩 블록이 되며, 그 결과로 더 깔끔하고 재사용과 유지보수하기 쉬운 코드가 됨.

#### 10.14 요약

스위프트와 같은 객체지향 프로그래밍 언어는 코드 재사용과 클래스 인스턴스 내의 데이터 캡슐화과 된 클래스를 생성하는 것을 장려함.

- 이번 장
    - 클래스와 인스턴스에 대한 기본 개념
    - 저장 프로퍼티, 연산 프로퍼티, 그리고 인스턴스와 타입 메서드
    - 클래스가 반드시 따르는 템플릿 역할을 제공하는 프로토콜의 개념
    - 불투명 반환 타입의 기본을 어떻게 구성하는지

- **데이터 캡슐화(data encapsulation)**: 클래스에 저장되고 접근될 수 있는 데이터는 오직 해당 클래스 내에 정의된 메서드만을 통해서 된다는 것. 클래스 내의 캡슐화된 데이터를 **프로퍼티** 또는 **인스턴스 변수(instance variable)**이라고 함.
